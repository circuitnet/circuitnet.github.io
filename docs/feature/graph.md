<div><h1 id="graph-features" tabindex="-1"><a class="header-anchor" href="#graph-features"><span>Graph Features</span></a></h1><p>To enable application for graph based methods, we further provide 54 gate-level netlists and 10242 instance placement information.</p><h2 id="gate-level-netlist" tabindex="-1"><a class="header-anchor" href="#gate-level-netlist"><span>Gate-level Netlist</span></a></h2><p>The gate-level netlists are the ones used in data generation. They are synthesised from 6 RISC-V designs with commercial 28 nm library and Synopsys Design Compiler(DC) with multiple variations. (see page <a class="route-link" href="/feature/properties.html">Feature</a> for detailed information about variations) The name of standard cell and IP is encrypted due to copyright issue.</p><p>There are 2 version of netlist, one is the original hierarchical version written by DC, and the other one is the flatten version written by Innovus for extracting graph.</p><p><strong>For ease of use, we extract the necessary information for forming graph from the flatten netlist.</strong> They are saved in the form of numpy array in graph_information.tar.gz.</p><p>(1) <strong>Pin Attributes</strong>: pin names, corresponding net index, node index.</p><p>(2) <strong>Net Attributes</strong>: net name.</p><p>(3) <strong>Node Attributes</strong>: node(instance) name, corresponding standard cell / IP name.</p><p>The array can be loaded with</p><p><code>numpy.load(FILE_NAME, allow_pickle=True)</code></p><p>Here is a simple example:</p><div align="center"><img src="/assets/netlist-BTAogb2W.jpg" width="300"></div><p>Pin Attributes: [[I,ZN,I,ZN], [0,1,1,2], [0,0,1,1]]</p><p>Net Attributes: [[in, n1, out]]</p><p>Node Attributes：[[inv_1, inv_2],[INV,INV]]</p><p>The pins with same net/node index belong to the same net/node, e.g., pin[1] &quot;ZN&quot; and pin[2] &quot;I&quot; have net index &quot;1&quot;, both of them belong to net &quot;n1&quot;; pin[0] and pin[1] have node index &quot;0&quot;, both of them belong to node &quot;inv_1&quot;. Thus, an adjacency matrix can be formulated through traversing the pin attributes array.</p><h2 id="instance-placement-cell-position" tabindex="-1"><a class="header-anchor" href="#instance-placement-cell-position"><span>Instance Placement (Cell Position)</span></a></h2><p>The instance, i.e., standard cell and IP, is placed at certain location on layout after placement stage in back-end design.</p><p>The placement information for each layout, i.e., the location of instances, is extracted from def and saved as a dictionary in instance_placement.tar.gz. It contains the name of instance (consistent with the ones in netlist) and the coordination for the bounding box of instance on layout.</p><p>e.g., InstanceN : [left, bottom, right, top]</p><p>For &quot;instance_placement_gcell&quot;, the coordinate is the same as the one in the image-like feature, which is in GCell grids, and the value indicates which GCell the instance is in.</p><p>For &quot;instance_placement_micron&quot;, the coordinate is in micron, and the value indicates the . It can be converted to GCell grids through dividing the width of GCell (available in the corresponding DEF files).</p><p>The dictionary can be loaded with</p><p><code>numpy.load(FILE_NAME, allow_pickle=True).item()</code></p><p>The placement information can be added into node attributes through indexing, since there is partially one-to-one correspondence from the node name from the node attribute array above to the keys in the instance placement dictionary (they are not exactly the same because innovus will add or delete cells, just take the intersection). With the additional placement information, tasks like congestion prediction can be completed with graph neural network.</p></div>
